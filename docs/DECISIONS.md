**2026-10-17, steps 3.1–3.5: shared kits.** `src/kits/` holds `easing.ts`, `text.ts`, `physics.ts`, `field.ts` and `render.ts`, tested in `tests/unit/kits.test.ts` (52 tests). Choices:
- Easing curves follow the easings.net definitions, so a prompt can name a curve ("ease-out-back") and any builder gets the same shape. The damped spring uses the same per-frame convention as the scenes: v += (target − x) × k × f, v ×= damping^f, x += v × f.
- Text: canvas only accepts keyword font stretches, so Anybody's 50–150% axis maps to the nearest keyword in canvas scenes (DOM scenes use the exact percentage). Letter boxes are measured from prefixes so kerning matches `fillText`. Letter outlines come from tracing the rendered letter's alpha with marching squares (consistently wound loops, holes included) plus Ramer–Douglas–Peucker simplification, since browsers don't expose glyph outlines.
- Physics: rigid boxes are four verlet corners held by six sticks (edges and diagonals), separated with the separating-axis test; `stepBodies` interleaves shape, box contacts and walls each pass so stacks don't sink or squash. Circles collide through a spatial hash rebuilt each frame with a counting sort; mass is area.
- Field: simplex noise with a seeded permutation (mulberry32), and a stable-fluids grid for `smoke` and `fire`.
- Render: `Batch` collects shapes into one path per color; glow is stacked strokes with additive blending, never `shadowBlur`; metaballs are computed on a coarse grid and scaled up.
- Benchmarks on this Mac (best of 30–40 runs, since other test files share the CPU): 2,000 colliding circles under 2ms per frame; a 48 × 48 fluid step under 2ms (64 × 64 takes about 3ms, so smoke and fire use 48 × 48 or smaller); 30 metaballs on a 160 × 100 grid under 2ms.

## 2026-10-17: 6.6 `moire` (⚠)

## 2026-10-17: 6.7 `tunnel` (⚠)
- Rings sit one "gap" apart; gap = max(base spacing, speed ÷ 3), so rings pass any spot at most 3 times a second at any speed. On top of that, `fly.ts` lets a ring pass the camera only if the last one passed at least 1/3 second ago (a ring that is early waits just short of the camera, too close to see). That makes the cap hold even if the speed setting jumps from the fastest to the slowest. `tests/unit/flash.test.ts` runs it flat out at 240, 60 and 20 frames a second with the speed jumping between extremes.
- The path is a simplex-noise curve (fixed seed): each ring is shifted by noise of its distance along the tunnel, minus the camera's own shift, so the tunnel bends ahead of you. Defaults: path width 0.6 and windiness 0.0003 (the first guess, 0.8 and 0.001, looked tangled).

**The lean process (no rule dropped: every number a slider or reasoned constant, phone version, still frame, reduced motion, pause, clean destroy, touch without blocking scroll, accessibility, flash test for ⚠ scenes, trademark test, OG image):**

5. **Once per chunk:** `npm run check`, the full `npm run test:e2e`, OG images, one DECISIONS entry, PROMPT_TESTS rows, PLAN ticks, HANDOFF, one commit and push.
6. **Prompt tests only for Spicy scenes** for now; all others get a "pending" row in `docs/PROMPT_TESTS.md`.

## 2026-10-21: `tokenstream` (#88), live
- **Stages:** one progress P plays five equal stages (type, split, stack, weigh, dock); scrolling or a sideways drag moves it, and left alone it plays forward, rests and plays back.
